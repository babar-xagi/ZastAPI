# ZastAPI⚡ — Step 008: What Are Expressions, Operators, and Assignment?

In Step 007, this became understandable:

```zig
const port: u16 = 8000;
var requests: u32 = 0;
```

But programs need to do more than **store values**.

They need to:

```text
add
subtract
compare
calculate
change state
make new values
```

For example:

```zig
2 + 3
```

or:

```zig
requests + 1
```

This brings us to three new ideas:

```text
Expression
Operator
Assignment
```

---

# 1. Start with a calculator 🧮

Imagine typing:

```text
2 + 3
```

into a calculator.

We begin with:

```text
2
3
```

The calculator performs:

```text
+
```

and produces:

```text
5
```

So:

```text
2 + 3
  ↓
  5
```

Programming does the same thing.

In Zig:

```zig
const total: u8 = 2 + 3;
```

The part:

```zig
2 + 3
```

produces the value:

```text
5
```

That piece of code is an **expression**.

---

# 2. What is an expression?

Our beginner definition:

> **An expression is code that produces a value.**

For example:

```zig
2 + 3
```

produces:

```text
5
```

And:

```zig
10 * 5
```

produces:

```text
50
```

And:

```zig
5 > 3
```

produces:

```text
true
```

So mentally:

```text
expression
    ↓
 produces
    ↓
  value
```

# 3. Expressions connect directly to Step 007

Remember:

```zig
const port: u16 = 8000;
```

Here:

```zig
8000
```

is itself a simple expression/value used to initialize `port`.

Now consider:

```zig
const port: u16 = 7000 + 1000;
```

The right side:

```zig
7000 + 1000
```

is evaluated.

It produces:

```text
8000
```

Then `port` gets that result.

```text
7000 + 1000
      ↓
     8000
      ↓
    port
```

So:

```zig
const port: u16 = 7000 + 1000;
```

and:

```zig
const port: u16 = 8000;
```

can ultimately give `port` the same value.

# 5. What is an operator?

An **operator** is a symbol that tells Zig to perform an operation.

For example:

```zig
2 + 3
```

The operator is:

```text
+
```

and the values it operates on are:

```text
2
3
```

Those are called:

# **operands**

So:

```text
  2      +      3
  │      │      │
operand operator operand
```

And the result is:

```text
5
```

Zig defines operators such as arithmetic, comparison, boolean, bitwise, and assignment-related operators. ([Zig Programming Language][1])

# 7. Expressions can use identifiers too

We don't need literal numbers everywhere.

Suppose:

```zig
const users: u32 = 10;
const admins: u32 = 2;
```

Then:

```zig
users + admins
```

means:

```text
10 + 2
```

which produces:

```text
12
```

So we can write:

```zig
const total: u32 = users + admins;
```

Mental picture:

```text
users ─────┐
   10      │
           ▼
           +
           │
           ▼
admins ───►12
   2
```

Then:

```text
total = 12
```

# 8. Expressions can contain other expressions

Consider:

```zig
2 + 3 * 4
```

There is more than one operation:

```text
+
*
```

The computer needs rules to decide what happens first.

Just like mathematics, operators have **precedence** rules. Zig documents operator precedence as part of its operator system. ([Zig Programming Language][1])

For now, if we want our intention to be extremely obvious, we can use parentheses:

```zig
2 + (3 * 4)
```

or:

```zig
(2 + 3) * 4
```

These produce different results:

```text
2 + (3 × 4)
= 14
```

while:

```text
(2 + 3) × 4
= 20
```

We'll study precedence separately later.

```text
  5
```

```text
 ↓
```

# 10. Comparison expressions ⚖️

Expressions don't always produce numbers.

Consider:

```zig
5 > 3
```

The question is:

> Is 5 greater than 3?

Yes.

So the result is:

```text
true
```

Remember Step 007:

```text
bool
```

means a boolean value:

```text
true
false
```

So:

```zig
const result: bool = 5 > 3;
```

produces:

```text
result
   ↓
 true
```

These are worth recognizing, but **don't memorize them yet**:

```text
==    equal to

!=    not equal to

>     greater than

<     less than

```

For example:


produces:


# 12. Very important: `=` and `==` are different

Beginners often mix these up.

Look:

```text
=
```

versus:

```text
==
```

They have very different jobs.

`=` is associated with giving/assigning a value:

```zig
requests = 5;
```

But:

```text
==
```

asks whether two values are equal:

```zig
requests == 5
```

Think:

```text
=     PUT / ASSIGN

==    ASK / COMPARE
```

That's an important distinction. 🧠

---

# 13. Real-life analogy

Imagine a whiteboard.

Writing:

```text
score = 10
```

means:

> Set the score to 10.

But asking:

```text
score == 10?
```

means:

> Is the score currently 10?

Completely different jobs.

```text
ASSIGN

score ← 10
```

versus:

```text
COMPARE

score == 10
     ↓
 true / false
```

# 14. What is assignment?

Suppose we have:

```zig
var requests: u32 = 0;
```

Initially:

```text
requests
   ↓
   0
```

Because we used:

```zig
var
```

the variable may later be changed.

We can write:

```zig
requests = 1;
```

Now:

```text
requests
   ↓
   1
```

That is an **assignment**.

Beginner definition:

> **Assignment changes a mutable variable to hold/refer to a new value.**

Zig's language semantics use the destination variable's type to constrain the value assigned to it. ([Zig Programming Language][1])

---

# 15. Declaration and assignment are different

This is subtle but very important.

First:

```zig
var requests: u32 = 0;
```

This is creating/declaring the variable and giving it its initial value.

Think:

```text
CREATE requests
       ↓
starting value = 0
```

Later:

```zig
requests = 5;
```

We're not creating `requests` again.

We're changing the existing variable.

```text
Declaration

var requests: u32 = 0;
        ↓
create it
```

versus:

```text
Assignment

requests = 5;
      ↓
change it
```

---

# 16. Why doesn't this work with `const`?

Suppose:

```zig
const port: u16 = 8000;
```

Then later:

```zig
port = 9000;
```

Zig rejects that.

Why?

Because Step 007 taught us:

```text
const
=
not reassigned
```

But this is fine:

```zig
var port: u16 = 8000;

port = 9000;
```

because:

```text
var
=
may change
```

# 17. Expressions can be used during assignment

Suppose:

```zig
var requests: u32 = 5;
```

We can calculate:

```zig
requests + 1
```

That expression produces:

```text
6
```

Then assign it:

```zig
requests = requests + 1;
```

Let's slow that down.

Before:

```text
requests = 5
```

Evaluate the right side:

```text
requests + 1
```

which means:

```text
5 + 1
```

producing:

```text
6
```

Then:

```text
requests = 6
```

So:

```text
BEFORE
requests = 5

CALCULATE
5 + 1 = 6

ASSIGN
requests = 6

AFTER
requests = 6
```

🔥 This is one of the fundamental patterns of programming.

---

# 18. Wait... how can `requests` appear on both sides? 🤔

This can look strange:

```zig
requests = requests + 1;
```

But read it in order conceptually:

```text
RIGHT SIDE FIRST

requests + 1
```

Current `requests` is:

```text
5
```

So:

```text
5 + 1
=
6
```

Then assign the result to the left:

```text
requests = 6
```

The old value has helped calculate the new value.

---

# 19. Zig gives us a shorter form

Instead of:

```zig
requests = requests + 1;
```

Zig supports:

```zig
requests += 1;
```

The Zig operator reference explicitly includes both addition and addition-assignment forms such as `a + b` and `a += b`. ([Zig Programming Language][1])

For our beginner mental model:

```zig
requests += 1;
```

means:

> Take the current `requests`, add `1`, and assign the result back.

So:

```text
requests = 5

requests += 1

requests = 6
```

---

# 20. Break `+=` apart

Look:

```text
+=
```

It's like combining:

```text
+
```

with:

```text
=
```

Conceptually:

```zig
requests += 1;
```

roughly corresponds to:

```zig
requests = requests + 1;
```

That's called a:

# **compound assignment operator**

# 22. Expression vs assignment

Let's separate these ideas.

This:

```zig
requests + 1
```

calculates something:

```text
expression
    ↓
new value
```

But it does not by itself mean:

> Replace `requests`.

If:

```text
requests = 5
```

then:

```zig
requests + 1
```

produces:

```text
6
```

while `requests` is still conceptually `5` unless we use that result somewhere.

To update it:

```zig
requests = requests + 1;
```

or:

```zig
requests += 1;
```

This distinction is huge.

# 33. Expressions don't have to use two operands

Not every operator has exactly two operands.

Some operations work with one value.

For example, boolean negation uses:

```zig
!
```

Conceptually:

```text
!true
  ↓
false
```

That's called a **unary** operation because it uses one operand.

An expression such as:

```zig
a + b
```

uses two operands and is called **binary** in the operator sense.

⚠️ Don't confuse that use of "binary" with Step 005's binary number system.

Same word, different context:

```text
binary number
→ uses 0 and 1

binary operator
→ operates on two operands
```

We'll revisit this later.

# 38. Key words from Step 008

| Concept                 | Beginner meaning                         | Example     |
| ----------------------- | ---------------------------------------- | ----------- |
| **Expression**          | Code that produces a value               | `2 + 3`     |
| **Operator**            | Symbol that performs an operation        | `+`         |
| **Operand**             | Value an operator works on               | `2`, `3`    |
| **Result**              | Value produced by an expression          | `5`         |
| **Assignment**          | Give/update a mutable variable's value   | `x = 5;`    |
| **Comparison**          | Ask about relationship between values    | `x > 5`     |
| **Compound assignment** | Calculate and assign in short form       | `x += 1;`   |
| **Precedence**          | Rules about which operation groups first | `2 + 3 * 4` |

Zig's official operator table documents these operator families and their precedence rules. ([Zig Programming Language][1])
