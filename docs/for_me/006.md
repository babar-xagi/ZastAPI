# ZastAPI⚡ — Step 006: What Are Memory, RAM, Storage, and Variables?

Now we are moving into one of the **most important ideas in programming**, especially for Zig. 🧠⚡

In Step 005 we learned:

```text

    ↓

```

But that creates a new question:

> When our program is running, where does it keep things like names, numbers, HTTP requests, users, routes, and responses?

That brings us to:

```text
Memory
RAM
Storage
Variables
```

They are connected, but they are **not the same thing**.

# 2. What is storage? 💾

Your computer probably has an:

```text
SSD
```

or sometimes:

```text
HDD
```

Storage is where files can stay even after the computer or program is turned off.

For example:

```text
ZastAPI/
├── build.zig
├── build.zig.zon
└── src/
    └── main.zig
```

Those files are stored on your SSD.

If you shut down your computer tonight and turn it on tomorrow:

```text
main.zig
```

is still there.

So our beginner definition is:

> **Storage = long-term place where files and data can remain.**

# 3. Real-life analogy: bookshelf 📚

Imagine putting a book on a bookshelf.

You leave the room.

You sleep.

You return tomorrow.

The book is still there.

That's like storage.

```text
save file
   ↓
SSD
   ↓
turn computer off
   ↓
turn computer on
   ↓
file still exists
```

This property is called:

```text
persistent
```

Meaning:

> it can remain there.

# 4. What is RAM? 🧠

RAM means:

```text
Random Access Memory
```

Don't worry about why it's called "Random Access" yet.

The important idea is:

> **RAM is fast working memory used while programs are running.**

Think of your desk.

You take a book from the bookshelf and place it on your desk because you want to work with it now.

```text
Storage
   │
   │ load
   ▼
RAM
   │
   ▼
CPU works with it
```

---

# 5. Why not just use the SSD for everything?

Because the CPU needs quick access to the information it's actively working with.

Very simplified:

```text
Storage
   ↓
large
persistent
slower

RAM
   ↓
temporary
fast
used while working
```

Your program therefore uses RAM as its active workspace.

# 6. What happens when a program starts?

Remember our executable?

Suppose eventually we build:

```text
zast-server.exe
```

Initially it exists on storage:

```text
SSD
│
└── zast-server.exe
```

Then we run it.

Conceptually:

```text
SSD
│
│ program starts
▼
RAM
│
│ program loaded
▼
CPU
│
└── executes instructions
```

So:

```text
Executable on storage
        ↓
Operating system loads program
        ↓
RAM
        ↓
CPU executes it
```

We'll learn the operating system properly later.

---

# 7. Does RAM keep things forever?

Usually no.

RAM is generally:

```text
temporary working memory
```

Suppose our running ZastAPI application has something in RAM:

```text
user_name = "Babar"
```

Then the application stops.

That memory is no longer ours.

If we need information to survive after the program exits, we normally save it somewhere persistent, such as:

```text
file
database
SSD
```

So:

```text
RAM
=
working now
```

while:

```text
Storage
=
keep for later
```

# 9. Then what does "memory" mean?

This word can be confusing because people sometimes use:



For our beginner lessons, when I say:


# 11. What is a variable? 📦

For now, think of a variable as:

> **A named place/value our program can use to remember some information.**

Imagine a labeled box:

```text
┌──────────────────┐
│ label: port      │
│                  │
│ value: 8000      │
└──────────────────┘
```

The label is:

```text
port
```

The value is:

```text
8000
```

So instead of constantly thinking:

```text
8000
```

we can refer to:

```text
port
```

# 17. Then why is it called a "variable"?

Good question.

Programming uses the general word:

```text
variable
```

for named data, but Zig makes a useful distinction.

You can have something that won't be reassigned:

```zig
const port = 8000;
```

and something that can change:

```zig
var count = 0;
```

Conceptually:

```text
const
port
8000

stays associated
```

while:

```text
var
count

0
↓
1
↓
2
↓
3
```

We'll explore that carefully later.

# 18. Variables and memory

Now connect variables back to RAM.

Suppose:

```zig
var count = 5;
```

Conceptually, while the program is running:

```text
Program
  │
  └── needs value 5
          ↓
      stored somewhere
          ↓
        memory
```

And the program uses the name:

```text
count
```

to work with that value.

Beginner mental model:

```text
variable name
      ↓
memory containing data
```

This is useful, but there is an important detail.

---

# 19. Important accuracy note 🧠

It is tempting to say:

> Every variable is a box in RAM.

That is useful for learning, but it is not always literally true.

A compiler may decide to keep something in:

```text
CPU register
```

or optimize it away completely.

So the more accurate model is:

> A variable is a named value/location your program can refer to; the compiler decides how that is represented physically.

For now, though, the labeled-box model is excellent.

# 25. What happens when the program ends?

Imagine:

```text
ZastAPI starts
    ↓
RAM allocated/used
    ↓
program runs
    ↓
program stops
```

The operating system can reclaim the program's working memory.

Conceptually:

```text
while running

RAM
┌─────────────┐
│ ZastAPI     │
│ data        │
└─────────────┘
```

then:

```text
program exits

RAM
┌─────────────┐
│ available   │
│ again       │
└─────────────┘
```

That is why RAM isn't where we normally keep important permanent data.

---

# 26. What does "save" mean?

Suppose your program has:

```text
score = 100
```

in working memory.

If you want that score tomorrow, you need to save it somewhere persistent.

Conceptually:

```text
RAM
score = 100
   ↓
SAVE
   ↓
Storage
score.dat
```

Next time:

```text
Storage
score.dat
   ↓
LOAD
   ↓
RAM
score = 100
```

So two important words:

```text
save
```

means RAM → persistent storage.

```text
load
```

means storage → working memory.
