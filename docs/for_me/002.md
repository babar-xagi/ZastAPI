# ZastAPI⚡ — Step 002: What Is a Program?

In Step 001 we learned what the files around our Zig project are.

Now we go **one tiny level deeper**.

Today we are **not changing ZastAPI yet**. Our goal is only to understand:

> **What exactly are we building when we write code?**

That thing is called a **program**. 🧠⚡

---

## 1. Imagine a robot 🤖

Suppose you have a robot.

By itself, the robot doesn't know what you want.

You give it instructions:

```text
1. Walk forward
2. Pick up the box
3. Turn right
4. Put the box down
```

The robot follows those instructions.

A computer works in roughly the same way.

We write instructions:

```text
instruction
instruction
instruction
instruction
```

The computer executes them.

A collection of instructions that tells a computer what to do is a:

# **Program**

Very simple mental model:

```text
Program
   =
instructions for a computer
```

---

# 2. Real-life analogy: a recipe 🍕

Imagine we want to make pizza.

We have a recipe:

```text
Pizza Recipe

1. Make dough
2. Add tomato sauce
3. Add cheese
4. Bake it
```

The **recipe itself doesn't cook anything**.

It only contains instructions.

Someone has to follow them.

```text
Recipe
   ↓
Cook follows instructions
   ↓
Pizza
```

Programming is similar:

```text
Source code
     ↓
Computer follows instructions
     ↓
Something happens
```

For example:

```zig
print("Hello");
```

roughly means:

> Computer, display `"Hello"`.

# 3. Your Zig file contains instructions

Inside:

```text
src/main.zig
```

there is Zig source code.

Think:

```text
main.zig
   ↓
instructions written in Zig
```

The important distinction is:

```text
main.zig ≠ running program
```

`main.zig` is just a **file containing source code**.

Just like:

```text
pizza_recipe.txt
```

isn't pizza. 🍕

---

# 4. Source code vs program

This distinction is very important.

### Source code

Code that **you write and read**:

```zig
pub fn main() void {
}
```

That's source code.

### Program

Something the computer can eventually execute.

So:

```text
Human
  │
  │ writes
  ▼
main.zig
(source code)
  │
  │ gets built
  ▼
Executable
  │
  │ runs
  ▼
Program doing something
```

We'll learn exactly what "build" and "compile" mean later.

Don't worry about them yet.

---

# 5. ZastAPI itself will eventually be a program/library

Right now:

```text
ZastAPI/
```

is mostly source files.

Eventually our code might say something like:

```zig
const zast = @import("zast");

pub fn main() !void {
    var app = try zast.App.init();

    app.get("/", home);

    try app.run();
}
```

That source code could eventually produce a running server:

```text
Browser
   │
   │ GET /
   ▼
ZastAPI⚡
   │
   ▼
"Hello"
```

So ZastAPI code tells the computer things like:

```text
open a network connection
wait for requests
find the matching route
run a function
send a response
```

Those are all instructions.

Thousands of tiny instructions together eventually become our framework.

# 6. What does "run a program" mean? ▶️

You will often hear:

```text
Run the program.
```

"Run" simply means:

> Start executing its instructions.

Imagine a movie.

The movie file exists:

```text
movie.mp4
```

but nothing happens yet.

When you press:

```text
▶ Play
```

the movie starts.

Similar idea:

```text
Program exists
      │
      │ run
      ▼
Computer starts executing it
```

When we type:

```powershell
zig build run
```

we're eventually asking Zig to:

```text
Build our project
      +
Run the resulting program
```

We'll break that command apart in a future step.

---

# 7. What does "execute" mean?

Another programming word:

# **execute**

Don't make it complicated.

It simply means:

> Perform an instruction.

Suppose our imaginary program contains:

```text
1. Print Hello
2. Print ZastAPI
3. Finish
```

Execution might look like:

```text
START
  │
  ▼
Print Hello
  │
  ▼
Print ZastAPI
  │
  ▼
FINISH
```

The computer goes through instructions.

That's **execution**.

---

# 8. Then where does execution begin? 🚪

A computer needs to know:

> Which part should I start from?

Imagine a 500-page book.

Someone tells you:

```text
Start reading.
```

You might ask:

> From which page?

Programs need a starting place too.

For our Zig executable, that special starting function is called:

```zig
main
```

You'll see something containing:

```zig
pub fn main(...)
```

inside:

```text
src/main.zig
```

For now, don't worry about:

```text
pub
fn
()
!
void
```

We're going to learn those one by one. 🔬

Today only remember:

```text
main
  =
starting point of our executable
```

# 10. `main.zig` and `main()` are NOT the same thing

This is a very useful distinction.

We have a **file**:

```text
main.zig
```

Inside that file we may have a **function**:

```zig
main()
```

Think:

```text
main.zig
   │
   │ file/container
   │
   └── main()
          function
```

Real-life analogy:

```text
Toolbox
└── Hammer
```

The toolbox is not the hammer.

Similarly:

```text
main.zig
└── main()
```

The file contains code.

The function is one part of that code.

# 11. What is a function?

Don't dive into functions yet—we'll give them their own step.

For now, imagine a function as:

> A named group of instructions.

Example conceptually:

```text
makeTea()
```

could mean:

```text
boil water
put tea in cup
pour water
```

So:

```text
main()
```

is a special function containing the program's starting instructions.
